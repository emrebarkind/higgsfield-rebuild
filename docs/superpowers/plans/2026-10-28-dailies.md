# Dailies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Dailies, a deployed, free, signed-out web app. You turn a still image (uploaded or AI-generated) into real camera moves rendered in the browser from an AI depth map, roll several takes, review them side by side, circle the best one and export it as MP4.

**Architecture:** A Next.js App Router app where almost everything runs on the client:
- A Web Worker runs Depth Anything V2 (transformers.js) and returns a depth map.
- three.js displaces a plane by that depth, and a camera pose function (`poseAt`) drives each move deterministically from a recipe (frame + move + params + seed).
- WebCodecs + mp4-muxer re-render a take offline into an MP4.
- IndexedDB holds frames, depth maps, shots and takes.
- The only server code is `/api/frame`, a rate-limited proxy to Pollinations for free text-to-frame.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind v4, three.js, @huggingface/transformers, mp4-muxer, idb-keyval, vitest, Vercel Hobby. Optional: @gradio/client.

**Spec:** `docs/superpowers/specs/2026-10-28-dailies-design.md` (rev. 2). Read it before Task 1; this plan argues from it.

## Global Constraints

- **Zero spend.** No paid API, no API keys, no Vercel add-ons that bill. Pollinations is called keyless.
- **Moves.** 9 ids (pan has two directions): `static`, `push-in`, `pull-back`, `pan-left`, `pan-right`, `orbit`, `crane-up`, `dolly-zoom`, `crash-zoom`.
- **Parameter ranges.** Strength 0–1. Duration 3–8 s. Easing `linear` | `ease-in-out` | `snap`. Lens 24 | 35 | 50 | 85 mm. Focus point x,y in 0–1. Handheld 0–1.
- **Shots and takes.** A shot holds at most 6 takes. Changing the frame, move or base params starts a new shot ("Roll new shot").
- **Frame input.** JPG/PNG/WebP, ≤ 10 MB. Downscale to ≤ 1536 px on the long edge before depth.
- **Export.** 720p or 1080p, aspects `16:9` | `9:16` | `1:1`, 30 fps, MP4 via WebCodecs, WebM via MediaRecorder as fallback.
- **Copy rules.**
  - Never call a 2.5D take "AI video".
  - Samples are labelled "Sample".
  - The experimental print is labelled "Experimental · free community GPU · may queue for minutes or be unavailable".
  - No fake progress. Export progress = frames rendered / total frames.
- **Visual tokens.** Graphite background (not `#000`), paper-white text. Tally red only for rolling/rendering, amber only for circled takes. No lime, no gradients.
- **Navigation.** Exactly three destinations: Studio (`/`), Moves (`/moves`), Dailies (`/dailies`).
- **Capture.** Commit `.agent-logs/` together with the code each session produced. Never edit log entries.

## Review Focus

1. **Extreme aspect ratios** (a 5:1 panorama, a 9:16 phone photo) must letterbox inside the output aspect, never stretch. Pinned by `fitFrame` tests in Task 3.
2. **Huge phone photos** (12 MP JPEG) must be downscaled before depth and stay responsive. HEIC is rejected with a clear message. Pinned by `prepareFrame` tests in Task 5.
3. **Refresh mid-shot or mid-export** must restore the current shot and its takes; export can simply be re-run. Pinned by the store round-trip test in Task 9.
4. **Double-clicking Roll or Export** must create one roll and run one export. Pinned by `rollTakes` guard tests in Task 4 and the `exportTake` single-flight test in Task 8.
5. **Browsers without WebGPU or WebCodecs** (Firefox, older Safari) must still work: WASM depth, WebM export, and say so once. Pinned by `pickExportPath` and `pickDepthDevice` tests in Tasks 5 and 8.

### Task 3: Move math (`poseAt`, `fitFrame`)

**Files:**
- Create: `src/lib/moves.ts`, `src/lib/__tests__/moves.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type MoveId = 'static'|'push-in'|'pull-back'|'pan-left'|'pan-right'|'orbit'|'crane-up'|'dolly-zoom'|'crash-zoom';
  export type Easing = 'linear'|'ease-in-out'|'snap';
  export type LensMm = 24|35|50|85;
  export interface MoveParams { strength: number; durationS: number; easing: Easing; lensMm: LensMm; focus: { x: number; y: number }; handheld: number; }
  export interface CameraPose { x: number; y: number; z: number; yawDeg: number; pitchDeg: number; fovDeg: number; }
  export interface MoveDef { id: MoveId; label: string; plain: string; defaults: MoveParams; diagram: { path: [number, number][]; startFrame: number; endFrame: number } }
  export const MOVES: Record<MoveId, MoveDef>;
  export const STRENGTH_CAPS: Record<MoveId, number>; // from spike step 2
  export function ease(e: Easing, t: number): number;
  export function poseAt(id: MoveId, p: MoveParams, t: number, seed?: number): CameraPose; // t in [0,1]
  export function fitFrame(frameW: number, frameH: number, outAspect: '16:9'|'9:16'|'1:1'): { scale: number; offsetX: number; offsetY: number; letterbox: boolean };
  ```
- Scene convention: the frame plane is at z = 0 and spans its aspect-correct width/height with height = 2. The base camera sits on +z at the distance where the lens FOV exactly frames the plane height.

- [ ] **Step 1: Write the failing tests.**
  - `poseAt t=0 is the base pose for every move at the same lens`: for all ids, `poseAt(id, p, 0)` deep-equals `poseAt('static', {...p, handheld: 0}, 0)` (within 1e-9).
  - `push-in moves toward the plane monotonically`: z at t = 0, 0.25, 0.5, 1 strictly decreases.
  - `pull-back is push-in reversed`: `poseAt('pull-back', p, t).z` equals `poseAt('push-in', p, 1-t).z` (with linear easing).
  - `dolly-zoom keeps subject height constant`: `z * tan(fov/2)` is constant within 1e-6 across t, and fovDeg changes by ≥ 15° at strength 1.
  - `strength is capped`: `poseAt(id, {...p, strength: 5}, 1)` equals the pose at `STRENGTH_CAPS[id]`.
  - `static with handheld 0 never moves`; with handheld > 0, the pose varies with t, is deterministic for the same seed, and differs across seeds.
  - `ease` returns 0 at t=0 and 1 at t=1 for every easing, and `snap` reaches ≥ 0.9 by t=0.5.
  - `fitFrame letterboxes a 5:1 panorama into 9:16` with `letterbox: true` and the full width visible; a 16:9 frame in 16:9 gives `scale 1, letterbox false`.
- [ ] **Step 2:** Run `npx vitest run src/lib/__tests__/moves.test.ts`. Expected: FAIL (module missing).
- [ ] **Step 3:** Implement `src/lib/moves.ts`.
  - Handheld is a smoothed 2-octave value noise seeded with mulberry32, with amplitude `handheld * 0.01` scene units plus `0.3°` rotation.
  - `pan-*` rotates yaw around the camera.
  - `orbit` moves on an arc around the focus point.
  - `crane-up` raises y with a compensating pitch toward the focus point.
  - `crash-zoom` is fov-only, using `snap` easing by default.
  - Each `MoveDef.plain` is one plain-English sentence, e.g. "The camera glides toward your subject."
- [ ] **Step 4:** Run the tests. Expected: all pass.
- [ ] **Step 5:** Commit: `feat: deterministic camera moves`.
